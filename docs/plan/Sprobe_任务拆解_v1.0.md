# Sprobe 1.0 可执行任务拆解与 AI 智能体分配

> 版本：v1.0  
> 日期：2026-11-21  
> 适用基线：后端文档 v1.3、前端文档 v1.2、契约 v1.0、`schema_version=1.0`、Agent 1.0.x  
> 文档性质：开发执行计划，不替代 `docs/backend/rust_v1_3.md` 与 `docs/frontend/sprobe_v1_2.md`；接口、指标、配置以源文档和机读契约为准。

## 0. 使用说明

### 0.1 这份计划解决什么

本计划把后端 v1.3 与前端 v1.2 的开发范围拆成可独立领取的任务，每项任务都给出：

- 任务目标与具体工作范围；
- 输入材料（读哪一章、哪个契约、哪个图示）；
- 交付成果（代码、测试、配置、文档或报告）；
- 优先级、前置依赖、建议执行波次；
- 预估工作量（人日，含实现、单测、自测，不含评审等待与返工）；
- 主责 AI 角色与协作角色；
- 可复核的验收标准。

### 0.2 分配原则

1. **一项任务一个主责**。主责角色对交付和验收负责，协作角色只提供接口、评审或测试支持。
2. **先冻结契约，再并行开发**。`A-02`、`A-03` 未完成前，前后端不得各自扩展字段。
3. **前后端写作用域隔离**。后端任务只改 `src/`、`tests/`、`ops/`、`Cargo.*`；前端任务只改 `console/`；文档任务只改 `docs/` 与根 `README.md`。
4. **所有任务必须能独立验收**。不能以“整体联调通过”代替单项验收。
5. **人工决策未确认时，任务保持阻塞**。AI 智能体不得自行选择前端框架、认证方式、公开范围或付费方案。

### 0.3 优先级定义

| 优先级 | 含义 | 处置 |
|---|---|---|
| P0 | 1.0 阻塞项，缺失会导致无法联调、无法验收或安全边界不成立 | 必须按波次完成，未完成不得进入下一 gate |
| P1 | 1.0 必须项，影响功能完整性或验收口径 | 在对应波次内完成；可接受少量返工 |
| P2 | 增强项或可延后项，不影响 1.0 核心闭环 | 资源不足时可砍，但需在变更记录中声明 |

## 1. AI 角色与职责

| 角色代号 | 角色定位 | 主要职责 | 不应承担 |
|---|---|---|---|
| `LEAD` | 架构/技术负责人 | 基线冻结、跨模块取舍、gate 评审、最终发布批准 | 不直接包办模块实现 |
| `PROTO` | 契约与接口负责人 | JSON Schema、错误码、字段路径、接口变更评审 | 不擅自改业务语义 |
| `BE-CORE` | 后端核心开发 | CLI/生命周期、调度、采集框架、规范化、快照、推送、WAL、健康引擎 | 不直接改前端契约消费代码 |
| `BE-LINUX` | Linux 采集开发 | `/proc`、`/sys`、`statvfs`、netlink、cgroup、aarch64 适配 | 不负责 Windows/macOS |
| `BE-PLAT` | 平台采集开发 | Windows PDH/IP Helper/服务、macOS Mach/IOKit 冒烟 | 不改变跨平台统一语义 |
| `FE` | 前端开发 | Console 页面、组件、类型、API 适配、异常态、可访问性 | 不实现服务端采集 |
| `INT` | 接口联调 | mock ingest、端到端联调、契约差异定位、联调报告 | 不替代 QA 做完整验收 |
| `QA` | 测试验证 | 单测/契约/集成/故障注入/性能/soak/UAT | 不修改生产实现来“让测试通过” |
| `SEC` | 安全与隐私 | 威胁模型、认证、脱敏、公开字段白名单、依赖审计 | 不单独决定产品公开范围 |
| `SRE` | 部署与运维 | CI/CD、systemd/容器/Windows 打包、监控、升级回滚 | 不改变应用语义 |
| `DOC` | 文档整理 | 文档同步、FAQ、Runbook、变更记录、链接校验 | 不写未经验证的功能承诺 |
| `HUMAN` | 人工决策人 | 框架、托管形态、认证、公开范围、预算、发布签字 | 不被 AI 角色替代 |

## 2. 执行总览

| 波次 | 日历 | 后端主线 | 前端主线 | 关键 gate |

```text
HD-03 框架决策
  → G-01 脚手架
  → G-02 类型/mock
  → G-03 壳/路由
  → G-04/G-05/G-06 页面

  → H-02 端到端
```

```text
B-03 快照契约稳定
  → E-01 Windows 采集
  → E-02 服务与打包
  → E-04 能力矩阵
  → H-03 跨平台故障验证
```

## 6. 验收与完成定义

### 6.1 后端 DoD

- `cargo fmt --check`、`cargo clippy`、`cargo test` 全绿；契约测试通过。
- `sprobe --once` 在 Linux Tier1 输出 8 类指标，快照通过 schema；缺失字段为 `null` 或 section 缺失，不伪造 0。
- 断网/服务端不可用 1 小时，WAL 未满时丢数为 0；重启可恢复；401 首次锁存 critical。
- 性能：启动 ≤2s 到 ready、RSS ≤64 MiB、CPU ≤单核 1%、fast p95 ≤100ms、二进制 ≤20 MiB。
- 72h soak 无泄漏、无崩溃、无 WAL 无限增长；22 项故障注入通过。
- 平台矩阵：Linux x86_64/aarch64 musl、Windows x86_64 为 Tier1；macOS 冒烟；FreeBSD 不作为发布产物。

### 6.2 前端 DoD

- 公开 `/overview` 匿名可访问；未登录详情跳登录；公开字段白名单生效，无 hostname/PID/cmdline 等敏感信息。
- 8 类异常态可复现；缺失值显示“—”，不显示 0；字段路径与契约一致。
- 首屏 JS ≤200 KiB gzip、LCP ≤2s、CLS ≤0.05；5 节点 24h 不超 Free 额度。
- Functions 202/400/401/409/413 正确；D1 幂等、latest + 1 分钟聚合、7 天保留；无重复计数。
- 部署可预览、可回滚；Secret 不入库；CSP/HSTS/XFO 生效。

### 6.3 联调与发布 DoD

- 5 节点端到端可见；总览/详情/历史一致；刷新不丢。
- 断网 1 小时、401/403、409、413、429、5xx、重启、旧 WAL、重复/乱序均有测试记录。
- UAT 所有 P0 通过；P1 有处置；遗留缺陷有 owner 与期限。
